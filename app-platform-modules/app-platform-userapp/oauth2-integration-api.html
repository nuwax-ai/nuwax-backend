平台 OAuth2
接入接口文档

平台作为 OAuth2 授权方（Authorization Server），三方应用通过标准 OAuth2 协议获取 access_token，并用该令牌调用平台开放接口。本文档覆盖接入配置接口、 四个协议端点、scope 白名单规则、凭证与令牌规格，以及可直接复制的端到端示例。

01

概览与接入流程

Overview / Endpoint Map

平台在 userapp 模块内实现完整的 OAuth2 授权方能力，以 user_project 作为接入应用配置表（projectType = ThirdApp）。 三方应用先在平台侧登记为「三方应用」并取得 Client ID / Client Secret，再通过标准协议端点换取令牌。

// 不透明令牌

令牌是随机不透明串而非 JWT，配合 Redis 存储实现即时撤销，避免引入签名密钥轮换问题。

// 前缀分派

access_token 固定以 oa- 开头，拦截器据此分派，无需每次请求先查一次 Redis。

// 独立令牌体系

access_token 不复用平台登录态，只能调用 scope 白名单内的接口，越权返回 403。

// 租户隔离

接入应用不跨租户。协议请求与设置页一样由域名 / x-tenant-id 解析租户，解析不到即失败。

端点总览

协议端点（面向三方应用）

方法路径登录态用途
GET /api/oauth2/authorize 必需 授权端点，签发授权码并 302 回跳
POST /api/oauth2/token 免登录 令牌端点，支持三种授权模式
GET POST /api/oauth2/userinfo access_token 返回授权用户公开信息
POST /api/oauth2/revoke 免登录 撤销令牌并清除授权关系

接入配置接口（面向平台内项目设置页）

方法路径用途
POST /api/user-project/oauth2/create 创建三方应用（自动生成凭证）
POST /api/user-project/oauth2/update 更新应用基本信息（名称 / 描述 / 图标）
GET /api/user-project/oauth2/setting/{projectId} 查询认证信息（不含密钥明文）
GET /api/user-project/oauth2/secret/{projectId} 查看密钥明文（审计留痕）
POST /api/user-project/oauth2/setting/save 保存主页地址与回调地址
POST /api/user-project/oauth2/credential/regenerate/{projectId} 重新生成凭证（旧凭证立即失效）
登录态约定 /api/oauth2/token 与 /api/oauth2/revoke 在免登录白名单内，靠 客户端凭证（client_id + client_secret）自行认证； /api/oauth2/authorize 与 /api/oauth2/userinfo 不在白名单，前者要求平台登录态、后者要求有效的 access_token。

接入流程

在平台侧创建三方应用

调创建接口落一条 project_type = ThirdApp 的项目记录，凭证在创建时即自动生成 （设置页接口在凭证缺失时也会兜底生成）。

配置回调地址

通过保存设置接口登记 redirect_uri。授权码模式要求回调地址精确匹配，未配置则无法发起授权。

引导用户授权，换取令牌

浏览器跳转授权端点 → 用户登录态下签发授权码 → 应用后端用授权码调用令牌端点，拿到 access_token 与 refresh_token。

调用接口

请求头携带 Authorization: Bearer <access_token>，仅可访问令牌所持 scope 覆盖的路径 —— 当前只开放 profile，即可调 /api/oauth2/userinfo； access_token 到期后用 refresh_token 轮换续签。

02

接入准备（设置页接口）

Credential & Setting · 需登录 + 空间权限

对应三方应用详情页「设置」tab 的 OAuth2 认证信息 卡片。先由创建接口落一条 projectType = ThirdApp 的项目记录，其余五个接口再对它做读写： 后者共用同一套前置校验 —— projectId 必须指向一条三方应用记录， 且当前登录用户对其所在空间有访问权限，否则一律拒绝（fail-closed）。

响应包装

本组接口返回平台统一的 ReqResult 包装：

ReqResult<T>
{
  "code": "0000",        // "0000" 成功；其余为失败码
  "displayCode": "0000", // 与 code 同值
  "message": "success",
  "data": { },
  "tid": "..."          // 链路追踪标识
}
注意 code 的取值 失败时 code 只区分 参数/业务错误（4000）、 未登录（4010）、空间权限不足（4030）与 系统异常（5000），具体原因以 message 为准。 细分业务码（如 3330 / 3335 / 3337）仅用于服务端 i18n 文案，不体现在对外 JSON 的 code 上。

2.0　创建三方应用

POST /api/user-project/oauth2/create 登录 + 空间权限

三方应用没有独立源表，创建即在 user_project 落一行 （project_type = ThirdApp、ref_id 为空，项目 id 即该表主键）。 建行后立即生成一对 OAuth2 凭证，返回体与查询认证信息一致 —— 但不含密钥明文，明文仍需另调 /secret/{projectId}。

参数位置类型说明
spaceIdbody选填空间 ID；不传则取当前用户的个人空间。显式传入需为该空间成员，否则 4030
namebody选填应用名称，≤128 字符；留空按当前语言取默认名
descriptionbody选填应用描述，≤512 字符
iconbody选填应用图标地址
回调地址不在这里填 redirect_uri 与 homepage_url 建行后经 POST /setting/save 维护，与设置页的编辑语义保持一致。 未配置回调地址时授权码模式无法发起（redirect_uri 缺失）。
与常规项目创建的区别 三方应用不是开发态项目：不分配沙箱（sandbox_id 留空）、 不创建用户工作目录、不建资料库协作目录，因此没有 workspacePath / sandboxId 参数。

curl -sS -X POST 'https://<tenant-domain>/api/user-project/oauth2/create' \
  -H 'Content-Type: application/json' \
  -H 'Cookie: ticket=<登录票据>' \
  -d '{"name":"我的三方应用","description":"示例接入应用"}'
200 OK

  "message": "success",
  "data": {

2.1　更新应用基本信息

POST /api/user-project/oauth2/update 登录 + 空间权限

更新三方应用的展示信息：名称、描述、图标。目标行必须是 project_type = ThirdApp，其余类型（常规项目、Agent、网页应用等）一律拒绝。 返回体与查询认证信息一致，便于前端一次请求刷新整张卡片。

参数位置类型说明
projectIdbody必填统一项目 ID（即创建接口返回的 projectId）
namebody选填应用名称，≤128 字符；传 null 不更新，传空串 / 空白串报错（不允许无名应用）
descriptionbody选填应用描述，≤512 字符；传 null 不更新，传空串即清空
iconbody选填应用图标地址；传 null 不更新，传空串即清空
null = 不更新，空串 = 清空 传入的非 null 值会先 trim 再写入，因此空串是有效指令（清空该字段）， 与 null（保持原值）语义不同。仅 name 例外：空值会被拒绝， 避免出现无名应用。
与 /setting/save 的空值语义不同 /setting/save 对 homepageUrl / redirectUri 采用 「空串等同不修改」的折叠语义，因此这两个字段目前无法清空，只能覆盖为新值。 两个接口在同一控制器内语义不一致，接入时请以各自参数表为准。
长度上限仅文档约定 name / description 的字符数上限对应数据库列宽， 服务端尚未做入口校验；超出会导致写库报错（5000）。接入方请在提交前自行截断。

POST /api/user-project/oauth2/setting/save 登录 + 空间权限

保存主页地址与回调地址，返回更新后的完整配置（结构同 2.2）。

参数位置类型说明

2.5　重新生成凭证

POST /api/user-project/oauth2/credential/regenerate/{projectId} 登录 + 空间权限

同时重新生成 clientId 与 clientSecret。 响应中的密钥明文仅本次返回，请立即保存。

旧凭证立即失效 重新生成后 clientId 发生变更，旧值在库中不再存在。由于令牌校验按 clientId 反查接入应用，该应用已签发的全部 access_token 与 refresh_token 会立即失效， 持有旧令牌的调用方需重新走授权流程。
200 OK
{
  "code": "0000",
  "message": "success",
  "data": {
    "clientId": "nwxa_2d17ab60c3f9481e057b2ac6d3f80194",
    "clientSecret": "nwxa_s_7f2c40a9e615d83b0471cf5a2e9860db31ac74fe0529b6d8"
  }
}

本组接口失败响应

code触发场景
4000projectId 为空；目标记录不存在；目标不是三方应用（仅三方应用支持 OAuth2 接入配置）；主页地址或回调地址格式不合法
4010未登录或登录超时（携带 Referer 时可能以 4011 跳转登录页）

03

授权码模式

authorization_code · 需要用户登录态

适用于「代表某个用户调用平台接口」的场景，是最完整也最推荐的接入方式。三步走：

浏览器跳转授权端点

三方应用把用户导向 /api/oauth2/authorize。用户此时须已登录平台， 平台校验客户端与回调地址后签发一次性授权码，302 回跳到 redirect_uri。

后端用授权码换取令牌

应用服务端调用 /api/oauth2/token，用授权码 + 客户端凭证换取 access_token 和 refresh_token。授权码一次性，用后立即作废。

携带令牌调用接口

请求头加 Authorization: Bearer <access_token>，即可访问令牌 scope 覆盖的接口。

3.1　授权端点

GET /api/oauth2/authorize 需平台登录态

校验客户端、回调地址与 scope，签发一次性授权码并 302 回跳。

参数类型说明
client_id必填平台分配的 Client ID
redirect_uri必填回调地址，必须与该应用登记值精确相等
response_type必填固定为 code
scope选填逗号分隔；留空表示授予该应用登记（或平台默认）的全部 scope
state选填防 CSRF 的透传值，成功与错误回跳都会原样带回，强烈建议携带

成功响应：302 回跳

302 Found · Location
https://example.com/oauth/callback?code=Kf3nQ8xLp2Rv7TzA9mWc4YbH6dJs1EgU&state=abc123

回跳参数统一做百分号编码；值为空的可选参数不会出现在回跳地址中（例如未传 state 则无该参数）。

失败响应

场景响应形式error
client_id 不存在 / 已停用 / 非三方应用 JSON 400，不跳转 invalid_client
未登记回调地址，或 redirect_uri 与登记值不一致 JSON 400，不跳转 invalid_request
response_type 不是 code 302 回跳 unsupported_response_type
scope 含平台不支持的项，或超出该应用被允许的范围 302 回跳 invalid_scope
同意页未启用（oauth2.auto-consent=false） 302 回跳 temporarily_unavailable
用户未登录 4010；携带 Referer 时以 4011 跳转登录页 —
为什么不跳转 当 客户端或回调地址不可信时，平台不会把错误重定向到该地址（否则等于把未验证的 redirect_uri 变成开放重定向跳板，参见 RFC 6749 §4.1.2.1），而是直接返回 JSON 错误。 只有在校验通过之后，才以 302 + error 参数的形式把失败原因交回应用。
当前版本无同意页 平台目前不渲染用户同意页（oauth2.auto-consent 默认 true）， 校验通过后直接签发授权码。该开关置为 false 时授权请求一律以 temporarily_unavailable 拒绝，不会静默放行。

3.2　令牌端点（授权码换令牌）

POST /api/oauth2/token 免登录 · 客户端凭证认证

请求体为 application/x-www-form-urlencoded。 客户端凭证可放在表单参数，也可用 HTTP Basic（Authorization: Basic base64(client_id:client_secret)）； 表单参数优先于 Basic。

参数类型说明
grant_type必填authorization_code
code必填授权端点返回的授权码
redirect_uri必填必须与授权请求中的值完全一致，缺失亦判失败
client_id必填也可改用 HTTP Basic
client_secret必填也可改用 HTTP Basic

成功响应

200 OK · Cache-Control: no-store
{
  "access_token": "oa-8Kx2mQv7Rn4TzLp9YcWb3HdJ6gUf1EsA0iVo5NtXrMk",
  "token_type": "Bearer",
  "expires_in": 7200,
  "refresh_token": "or-3Pz9WqLm6Tv2Rk8YbNc4HdJf1EgU5Ax7Vo0NtXrMsQ",
  "scope": "profile"
}

令牌端点的响应体是 RFC 6749 规定的扁平 JSON，不被平台的 ReqResult 包装，且固定带上 Cache-Control: no-store 与 Pragma: no-cache。

失败响应

HTTPerror触发场景
401invalid_clientclient_id 不存在 / 已停用；client_secret 不正确；未提供客户端凭证
400unsupported_grant_typegrant_type 不是三种受支持模式之一
400invalid_grant授权码无效、已过期或已被使用；授权码属于另一个客户端；redirect_uri 缺失或与授权请求不一致
400invalid_scope请求的 scope 非法或超出应用允许范围
400 · 错误响应结构
{
  "error": "invalid_grant",
  "error_description": "authorization code is invalid, expired or already used"
}
授权码一次性 授权码在令牌端点被取用后立即作废（无论后续校验是否通过），因此重放同一个授权码一定失败。 授权码默认有效期 300 秒。

3.3　用户信息端点

GET POST /api/oauth2/userinfo Bearer access_token

返回令牌所属授权用户的公开信息。要求令牌持有 profile scope。

请求
GET /api/oauth2/userinfo
Authorization: Bearer oa-8Kx2mQv7Rn4TzLp9YcWb3HdJ6gUf1EsA0iVo5NtXrMk
200 OK
{
  "sub": "1024",
  "user_id": 1024,
  "name": "示例用户",
  "avatar": "https://.../avatar.png",
  "tenant_id": 1
}

响应同样是扁平 JSON，不带 ReqResult 包装。sub 为字符串形式的用户 ID。

04

刷新令牌

refresh_token · 轮换机制

access_token 到期后，用 refresh_token 换取新的一对令牌，避免用户重新授权。

POST /api/oauth2/token 免登录 · 客户端凭证认证
参数类型说明
grant_type必填refresh_token
refresh_token必填上一次令牌响应中返回的 refresh_token
client_id / client_secret必填也可改用 HTTP Basic

响应结构与授权码模式一致，含新的 access_token 与 新的 refresh_token。

令牌轮换 刷新成功后旧 refresh_token 立即作废，应用必须用响应中的新值替换本地存储的旧值。 重复使用旧 refresh_token 会返回 invalid_grant。
HTTPerror触发场景
401invalid_client客户端凭证错误或客户端已停用

参数类型说明

  • 客户端认证失败仍返回 401 + invalid_client。

scope 与接口白名单

Scope Registry · 权限边界

access_token 不是平台登录令牌，只能调用显式开放的接口。每个 scope 对应一组路径模式， 令牌校验时按请求路径逐条匹配，未命中即拒绝（fail-closed）。

平台支持的 scope

scope放行路径用途
profile /api/oauth2/userinfo 读取授权用户自身信息

默认值应用未配置允许范围时，平台授予 profile 一项。

当前仅开放 profile access_token 只能读取授权用户自身信息，尚不能调用平台的开放接口 （/api/v1/**）。开放接口的 scope 后续再放，届时本页会同步更新。

三层判定规则

应用允许范围

取自接入应用的 oauth_scope 配置（逗号分隔）。为空时取平台默认 profile；非空但全部非法时回落默认值，避免出现「零权限」的哑客户端。

授权时收窄

授权请求携带的 scope 必须是应用允许范围的子集。 含平台不支持的项、或超出允许范围 → invalid_scope。 留空则授予全部允许范围。

调用时逐请求判定

每次携带 access_token 的请求，其路径必须命中该令牌所持 scope 的任一路径模式， 否则返回 403（平台错误码 4030，权限不足）。

动态收窄 若管理员事后收窄了应用的 oauth_scope，已签发的令牌会同步收窄 —— 令牌原 scope 与当前允许范围取交集后再做路径判定。换句话说，权限收紧立即对存量令牌生效， 无需等待令牌过期。
常见 403 场景 用 access_token 去调 /api/oauth2/userinfo 以外的任何接口 —— 当前 profile 只放行该路径，其余路径一律返回 403。

凭证与令牌规格

Credential Format · TTL · Invalidations

格式

名称前缀主体熵
Client IDnwxa_32 位小写 hex16 字节
Client Secretnwxa_s_48 位小写 hex24 字节

令牌由 SecureRandom 生成，是不可猜测的不透明字符串（非 JWT）， 本身不携带任何可解出的信息，必须回源校验。

有效期

对象默认 TTL续期 / 轮换
授权码300s一次性，取用即作废
access_token7200s滑动续期：每次校验通过后重置为满 TTL
refresh_token2592000s（30 天）每次刷新时轮换，旧值立即作废
授权关系2592000s（30 天）刷新时依据其存在性判断授权是否仍有效
滑动续期的含义 access_token 每被成功校验一次，其过期时间就重置为完整 TTL。因此 持续活跃的调用不会因 7200 秒到期而中断；但令牌的绝对存活时间可能超过 7200 秒。 长时间空闲后，令牌会在最后一次调用后的 7200 秒过期。

令牌失效的全部场景

触发动作影响范围
用户撤销授权（/revoke）该用户对该客户端签发时间早于撤销时刻的全部令牌立即失效，且 refresh_token 无法再续签
调用「重新生成凭证」client_id 变更，该应用全部令牌立即失效（含所有用户）
应用停用 OAuth2 接入（oauth_enabled = false）该应用全部令牌立即失效，协议端点返回 invalid_client
应用被删除 / 类型变更同上，按「客户端不存在」处理
管理员收窄 oauth_scope存量令牌权限同步收窄，越权路径返回 403
授权用户被禁用或删除该用户相关令牌请求被拒（账号不可用）
access_token 自然到期仅该令牌失效，可用 refresh_token 续签
refresh_token 被轮换旧的 refresh_token 立即作废

端到端接入示例

Walkthrough · curl

把 <tenant-domain> 换成本租户的访问域名（协议请求的租户由域名或 x-tenant-id 头解析，接入应用不跨租户）。

步骤 1　拼接授权链接

回跳地址必须做 URL 编码，且与登记值精确一致：

浏览器跳转
https://<tenant-domain>/api/oauth2/authorize
  ?client_id=nwxa_9f4c1e77b2a05d386e1f7c4a0b95d2e8
  &redirect_uri=https%3A%2F%2Fexample.com%2Foauth%2Fcallback
  &response_type=code
  &scope=profile
  &state=Xk92LmQ7

用户授权后浏览器被回跳到 https://example.com/oauth/callback?code=...&state=Xk92LmQ7， 应用需校验回跳的 state 与发起时一致。

步骤 2　换取令牌

bash
curl -sS -X POST 'https://<tenant-domain>/api/oauth2/token' \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -d 'grant_type=authorization_code' \
  -d 'code=Kf3nQ8xLp2Rv7TzA9mWc4YbH6dJs1EgU' \
  -d 'redirect_uri=https://example.com/oauth/callback' \
  -d 'client_id=nwxa_9f4c1e77b2a05d386e1f7c4a0b95d2e8' \
  -d 'client_secret=nwxa_s_3b8e5a1f9c47d0268ba3e5f1c9047d2a6e83b5f0c17a94d2'
响应
{
  "access_token": "oa-8Kx2mQv7Rn4TzLp9YcWb3HdJ6gUf1EsA0iVo5NtXrMk",
  "token_type": "Bearer",
  "expires_in": 7200,
  "refresh_token": "or-3Pz9WqLm6Tv2Rk8YbNc4HdJf1EgU5Ax7Vo0NtXrMsQ",
  "scope": "profile"
}

步骤 3　调用用户信息

bash
curl -sS 'https://<tenant-domain>/api/oauth2/userinfo' \
  -H 'Authorization: Bearer oa-8Kx2mQv7Rn4TzLp9YcWb3HdJ6gUf1EsA0iVo5NtXrMk'

步骤 4　调用其它接口

当前平台尚未开放任何开放接口（只支持 profile），用该令牌调用 /api/oauth2/userinfo 以外的路径一律返回 403 + 4030，例如：

bash · 预期 403
curl -sS 'https://<tenant-domain>/api/v1/...' \
  -H 'Authorization: Bearer oa-8Kx2mQv7Rn4TzLp9YcWb3HdJ6gUf1EsA0iVo5NtXrMk'

步骤 5　刷新令牌

bash
curl -sS -X POST 'https://<tenant-domain>/api/oauth2/token' \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -d 'grant_type=refresh_token' \
  -d 'refresh_token=or-3Pz9WqLm6Tv2Rk8YbNc4HdJf1EgU5Ax7Vo0NtXrMsQ' \
  -d 'client_id=nwxa_9f4c1e77b2a05d386e1f7c4a0b95d2e8' \
  -d 'client_secret=nwxa_s_3b8e5a1f9c47d0268ba3e5f1c9047d2a6e83b5f0c17a94d2'

响应里的 refresh_token 是新值，请用它覆盖本地存储的旧值。

步骤 6　撤销授权

bash
curl -sS -X POST 'https://<tenant-domain>/api/oauth2/revoke' \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -d 'token=or-3Pz9WqLm6Tv2Rk8YbNc4HdJf1EgU5Ax7Vo0NtXrMsQ' \
  -d 'token_type_hint=refresh_token' \
  -d 'client_id=nwxa_9f4c1e77b2a05d386e1f7c4a0b95d2e8' \
  -d 'client_secret=nwxa_s_3b8e5a1f9c47d0268ba3e5f1c9047d2a6e83b5f0c17a94d2'

# 200 OK
