00速览：四种查法怎么拼参数

同一接口，四种用途互不冲突，可以叠加筛选条件。

一句话

官方看 scope=official；全部空间什么都不传；指定空间传 spaceId；我已启用传 connectionEnabled=true。四者可组合，例如「空间 57 里我已启用的」= ?spaceId=57&connectionEnabled=true。

#要查什么请求本次实测条数
1 所有官方连接器 GET /providers?scope=official 1283
2 所有空间的连接器（我有权限的全部空间，含官方） GET /providers（不传 spaceId） 1298
3 指定空间的连接器 GET /providers?spaceId=57 1298
4 我自己已启用的连接器 GET /providers?connectionEnabled=true 8

为什么 2 和 3 都是 1298？因为官方连接器（1283 条，spaceId=0）对每个空间都可见，而该账号除了空间 57 之外没有别的空间自建连接器。所以「全部空间」= 官方 1283 + 空间自建 15 = 1298；「空间 57」恰好也是 1283 + 15。若你只想看空间自建、不要官方，加 scope=space：?scope=space 得到 15 条。

02四种查法详解

每张卡：怎么调、返回多少、要看哪个字段。

① 所有官方的连接器scope=official实测 1283 条

只查平台官方目录（spaceId=0，managedBy=system、source=open_connector 等），不含任何空间自建。传了 scope=official 后 spaceId 会被忽略，也不要求调用方是任何空间的成员。

GET请求
/api/connector/providers?scope=official&pageSize=20&pageNum=1

返回要点：每条 spaceId 恒为 0；status 默认只返回 enabled 的官方条目（要含停用的需显式传 status=all）。

叠加「我启用的官方」：?scope=official&connectionEnabled=true → 实测 5 条（ably_control、anthropic、asana、deepseek、add02）。

② 所有空间的连接器不传 spaceId实测 1298 条

不传 spaceId 时，后端按当前用户的全部空间解析（自己取用户的空间列表，而不是让调用方自报），返回官方 + 各空间自建。

GET请求
/api/connector/providers?pageSize=20&pageNum=1

返回要点：spaceId=0 的是官方，其余是各空间自建。实测 1298 = 官方 1283 + 空间自建 15。

只要空间自建、不要官方：加 scope=space → 实测 15 条。

③ 指定空间的连接器spaceId=57实测 1298 条

传 spaceId 即进入单空间视图，会校验你对该空间的成员权限（不是成员会报错，见第 07 节）。返回 = 该空间自建 + 官方（官方对每个空间可见）。

GET请求
/api/connector/providers?spaceId=57&pageSize=20&pageNum=1

返回要点：本次实测该账号除空间 57 外无其他空间自建，所以条数与「不传 spaceId」相同（1298）；换账号或换空间会不同。只要空间 57 自建：?scope=space&spaceId=57 → 实测 15 条，且全部为 spaceId=57，不含官方。

④ 我自己已经启用的连接器connectionEnabled=true实测 8 条

按「我是否启用了该连接器的任一连接」过滤。判据是连接行的用户开关 enabled=1，不掺凭证健康度——所以「启用了但 token 过期」的连接器仍算已启用（真去执行才会报 connection_expired）。

GET请求
/api/connector/providers?connectionEnabled=true&pageSize=20&pageNum=1

返回要点：8 条 = github、ably_control、anthropic、asana、deepseek、add02、s_add02、s_qwen_image，connected 与 connectionEnabled 全为 true。

反向查询：?connectionEnabled=false → 实测 1290 条（未连接的 + 连了但停用的），与 8 条互补，8 + 1290 = 1298 ✓。

全部为 Query 参数，均为可选，可自由组合。

scopeofficial / space不传official=仅官方；space=仅空间自建；不传=两者都要

05排序：已启用的排前面

固定四档，服务端不接受排序参数。要别的排法请在客户端二次排序。

档含义判据建议动作
0可用connected ∧ connectionEnabled ∧ 凭证 status='active'直接执行
1已启用，但凭证异常已连接且启用，凭证 expired / error需重新授权或修凭证
2已连接，未启用connected=true ∧ connectionEnabled=false可一键启用（凭证仍在）
3未连接没有连接行需建连

档内按目录权重 sort_order ASC, id ASC —— 与改动前的顺序完全一致，所以「未连接」这一大档的顺序没有任何变化。

线上实测证据

不传任何过滤，pageSize=10 取前 10 条：前 8 条恰好是全部 8 个已启用连接器（github、ably_control、anthropic、asana、deepseek、add02、s_add02、s_qwen_image），第 9 条起转入未连接（ima、todo_demo）。connected=true 与 connectionEnabled=true 各 8 个，与档 0 完全对齐。

档 0 与档 1 在接口上不可区分（都表现为 connected=true + connectionEnabled=true）。凭证健康度不对外暴露——这是有意的：客户端只需要知道「能不能用我启用的」，真过期了在执行时会拿到明确的 connection_expired，届时再引导重新授权。所以做界面时不要试图用这两个标注推断凭证状态。

分页正确性

GET?connectionEnabled=true&pageSize=5 翻页

排序权重会变化：你启停连接后，同一条目在不同档之间移动，页码会变。做「翻页加载」的界面时，建议在列表顶部标明「已启用优先」，或按需锁定一次快照，避免用户在翻页途中看到条目跳位。

07边界与错误

实测过的错误情形，以及一个容易误判的坑。

情形响应说明
未登录 / 会话过期 HTTP 200 + code:"4010"
Not signed in or session expired.		 不是 HTTP 401，必须按 code 判断
传入不存在的空间 code:"4000"
空间不存在		 ?spaceId=999999 实测；不存在的空间直接拒绝
传入非成员空间 权限类错误 传 spaceId 会校验成员权限；未构造实测
参数写错值 忽略并按默认值处理 如 connectionEnabled=yes 无法解析为布尔，按「不传」处理，不会报错

「过滤没生效」与「没传参数」必须分清。?connectionEnabled=true 少写一个字母（或写成 yes）时，接口不报错，而是当成没传——你会拿到全量 1298 条，很容易误以为「过滤生效了但数据没分类」。任何过滤后条数没有明显变化时，先核对参数拼写。

反向过滤的语义：connectionEnabled=false 包含「从未连接」和「连了但停用」两类，实测 1290 = 1298 − 8。若要精确表达「连了但停用」，请组合 ?connected=connected&connectionEnabled=false。

10免鉴权（no_auth）连接器怎么处理

不建连接也能直接执行；但一旦建了连接，启停开关就管得住它——「统一管理」在免鉴权上的落点就在这里。

一句话

authType=no_auth 的连接器，平台不收集、不注入任何凭证。一条连接都没建时执行会被放行（列表里 connected=false 不是异常）；建了连接之后，那条连接的启停状态就成为执行的前置条件——与 api_key / oauth2 完全同构。

建了连接和没建连接，差在哪

该连接器的连接情况执行结果为什么
一条连接都没建放行，直接执行免鉴权本就不需要凭证，「用哪条连接」无从谈起
建了，且启用 + 凭证正常用这条连接执行与其它认证方式一致
建了，但被停用connection_disabled连接一旦存在，就代表你对这个连接器的管理意愿——停用 / 失效必须算数，否则启停开关在免鉴权上是空转的
建了，但凭证 expiredconnection_expired

POST /actions/{id}/test

如果确实想给它建一条连接

免鉴权连接器的连接不装凭证：injectAuth 见到 NO_AUTH 直接跳过，不会往请求里塞任何东西，凭证字段可以完全不传（服务端 NO_AUTH 分支为空实现）。它承载的是启停状态与「我连过它」的归属，不是密钥。

前端已经给了入口：免鉴权连接器的卡片上直接显示「连接」按钮，抽屉里不需要填任何字段，确认即建。建完即可在「已连接」里统一启停或断开。想让它进「我的连接器」并受启停管理，点一下连接即可。

POST建一条空凭证连接
POST /api/connector/connections/api-key
{
  "providerService": "s_add01",
  "spaceId": 57            // 空间自建必填；官方连接器不要传
  // fields 省略或传 {} 均可
}

→ 建出的连接：status="active"，enabled=true

建不建连接，决定它受不受启停管理。不建：执行永远放行，但 connected / connectionEnabled 恒为 false，永远落在四档排序的档 3，也不出现在 ?connectionEnabled=true 里——相当于「不受管」。建了并保持启用：进档 0、出现在「我已启用」结果里，且可用 /connections/{id}/status 一键停用；停用后执行会报 connection_disabled，不会像以前那样被静默放行。

反面提示：connectionId 一旦传了，校验就全部生效——传一条已停用的连接会报 connection_disabled，传一条不存在的连接会报 connection_not_found（实测确认）。所以免鉴权连接器如果要传 connectionId，就得保证那条连接是启用且健康的，否则「本来不传就能跑」的事反而会失败。
